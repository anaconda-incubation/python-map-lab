# Mobile redesign: implementation and validation

September 10, 2026 · Candidate branch: `mobile-redesign` · Baseline: `504362d` on `main`

The candidate is a separate worktree. The main checkout and published site have not changed. The local production preview is at **http://127.0.0.1:4177/**.

## What changed

The opening screen now puts a usable map ahead of the reading. Learn and Experiment share a single map, with compact selectors and a consistent question → observation → explanation → optional Python sequence. Phones have a dedicated Map/Python workspace, an expanded map focus view, and a Layers sheet. Desktop retains a broad map beside the explanation and an optional full-width view.

Default maps are generated by executing the canonical lesson Python in advance. Their geometry, exact numerical sample layout, thumbnails, and textures are versioned assets. Reading and selecting examples do not start Python. Opening the editor loads CodeMirror and prepares Pyodide; arbitrary edits still execute real NumPy and redraw the map.

Light, Dark, and System appearance work across the page, map, labels, editor, and dialogs. Scrolling is native. Animated projection transitions remain independently controllable.

## Performance evidence

The comparison used built static sites on the same machine and in-app browser. Main was built unchanged; `scripts/profile-baseline.mjs` made an isolated temporary copy with a local measurement overlay. No application changes were made to main for measurement.

- **Initial reader resource transfer:** about **7.09MB → 1.48MB**, roughly 79% less in this local test. These are Resource Timing totals for requests visible to the top document, excluding the HTML and child-worker downloads. The baseline also downloaded Python resources inside its worker; those are not counted here. Vite's local handling/compression of raw GeoJSON can differ from Cloudflare, so this is not a claim of a measured 79% production reduction.
- **Reader startup:** no initial CodeMirror, PythonPanel, KaTeX, or Pyodide-worker request in the candidate. The baseline eagerly loaded the editor, mathematics, and worker.
- **Renderers:** two canvases in the original; one active renderer in the candidate, including after repeated mode changes and graphics recovery.
- **Final candidate warm reloads at 390×844:** first interactive frames occurred **402, 383, and 397ms after navigation**. Within those totals, map initialization took 66, 48, and 63ms; map fetch/decode took 23, 19, and 20ms. The measured LCP entries were 96, 60, and 72ms, with no observed long tasks in those three initial-load samples. LCP is not a measure of completion of a WebGL scene.
- **Baseline warm reloads at 390×844:** the old readiness flag appeared at 700 and 720ms; its first measured navigation was 953ms. That flag is a slightly different readiness signal from the candidate's actual first rendered frame. These are observations, not a statistically controlled device benchmark.
- **Animations:** a Globe → Mercator transition measured 899ms including endpoint loading, retaining the intended approximately 850ms morph. Reduced motion settles without the animated interval. Rapid selection back to the current projection was checked against the displayed endpoint.
- **Idle behavior:** settled frame counts stopped advancing; the existing demand-driven renderer is preserved. Hidden/offscreen rendering is paused. This does not claim a measured battery improvement.

The diagnostic `cumulativeLayoutShift` is a simple sum of observed shifts, not the official session-window CLS calculation. Its interaction entry is not an INP estimator. No field Core Web Vitals score, network/CPU-throttled result, or physical-phone frame-rate result is claimed.

## Remaining device and release checks

### Phone-width and dropdown refinement

Following the visual review, phone maps at viewport widths up to 600px now extend to the page edges. Portrait pane heights follow the projection's baked proportions, with a modest minimum for very small screens. At 476×1173, AuthaGraph is 476×206 and Mercator is 476×317, compared with the previous fixed 400px height. At 390×844, Mercator is 390×260. The camera uses a smaller gutter, and compact Mercator uses a 3:2 frame and fits the width, allowing polar edges to crop instead of forcing a square viewport. A visible note explains this; Expand restores the full projection. The globe and other projections retain their complete outlines, and globe exploration shares the same initial framing as Reset. Successful custom runs update the pane from their actual bounds.

Native dropdown options now set both their foreground and background colors explicitly. After Light → Dark, the inspected option colors changed from dark text on `#f7f8f3` to light text on `#0c1410`. Native popup pixels are not included in the browser screenshot API, so this verifies the applied styles and selection behavior rather than certifying every platform's native menu rendering.

Mercator, Equal Earth, Globe, expansion/return, narrow phone widths, landscape, and desktop were checked again. The full check suite still passes: 126 tests, lint, TypeScript, and production build. Projection formulas and notebook content did not change.

### Device and release limitations

The available browser interface supports responsive viewports, DOM/AX inspection, screenshots, keyboard/mouse interaction, and local app diagnostics. It does not provide physical iPhone Safari or Android Chrome, real touch/software-keyboard behavior, mobile GPU memory pressure, or network/CPU throttling. Those checks need representative devices before a broad launch. A full screen-reader session and field Web Vitals collection also remain unmeasured.

Overview deliberately uses coarser coastlines; the user can request Detailed. The generated collection is about 282MB on disk, but only the selected map is fetched. Individual files are below Cloudflare Pages' 25MiB limit (largest about 11.7MB); decoded high-detail geometry and active morph endpoints can still be substantial on low-memory devices. The cache limits are documented in `GENERATED_MAPS.md`.

The only production-build warning is Vite's advisory about the separately loaded Three.js chunk exceeding 500KB before compression (about 128KB gzip). It is not part of the initial reading shell. No unresolved test/build error remains.
